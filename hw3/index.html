Part 1: Ray Generation and Scene Intersection

For the rendering pipeline, first we need to generate rays from the camera into the scene. The renderer treats the camera as a pinhole located at the camera origin in camera space. In front of this pinhole, we have a virtual sensor plane at z = -1 as with the diagram shown from spec. Each image sample corresponds to a point on this sensor plane, and a ray is formed by starting at the camera origin and passing through that point in the sensor plane.

In our implementation of Ray Camera::generate_ray(double x, double y) const, the input (x,y) is given in normalized image coordinates, where both values are within the [0,1] range. The bottom left corner of the image maps to the bottom left corner of the sensor plane, and vice versa for other corners. To convert this normalized coordinate into a point on the sensor, we first converted the horizontal and vertical field of view from degrees to radians. Then we scaled / recentered the sample with:

double sensorX = (2 * x - 1) * tan(hFovRad / 2.0);
double sensorY = (2 * y - 1) * tan(vFovRad / 2.0);

This gives the sensor space point (sensorX, sensorY, -1) to match the actual size of the sensor. After normalizing this vector, we rotate it into world space with the camera to the world matrix, and use the camera position as the ray origin. We make sure to initialize the ray's valid t-range using near and far clipping planes. Once this ray is generated, it is tested against scene primitives such as triangles and spheres in parts 3, 4. For each primitive, the renderer checks whether the ray intersects it with the valid t range, and if it does, it updates the ray to keep the nearest hit. Therefore, ray generation determines where the camera is looking, and primitive intersection would determine what object is being "hit" upon and visible along that direction.

Part 2: Bounding Volume Hierarchy

Task 1

We built the BVH recursively over [start, end) range of primitives stored in BVHAccel::primitives.

For bounding box and leaves: for each call, we computed the axis aligned bounding box of all primitives in the range by unioning each primitive's get_bbox(). Then, we allocated a BVHNode with that box. If the number of primitives (n = end - start) is less than or equal to max_leaf_size, we assign the node as a leaf by setting start and end to those iterators so the leaf references exactly the primitives in this range, and return.

Otherwise, we split the axis. To do so, we compute a second box, the centroid bounds, by expanding around each primitive's get_bbox().centroid. Then, we take extent.x, y, z and choose the split axis with the largest spread. Spreading along the longest direction of the centroid would separate geometry more evenly in space than if we were to choose an arbitrary fixed axis.

After deciding the largest axis to split upon, we partition and assign children. We partition the range with std::nth_element so that primitives with centroid coordinate less than the median on the chosen axis lie in the left, and the rest on the right. We use mid = start + n/2 as the pivot. We chose a median split, because this keeps the BVH well-balanced (by definition of median) with an equal number of primitives on either side, leading to a tree depth with O(log n). We want the tree to be as balanced as possible, so it reduces the worst case number of node traversal during ray intersection, improving performance consistency which is the point of this task.

Task 2

In BBox::intersect, we implemented the slab method to test whether a ray intersects an axis-aligned bounding box. The box is treated as the intersection of three pairs of parallel planes (slabs), one pair per axis. For each axis, we compute the t values where the ray enters and exits that slab using tNear = (min[i] - ray.o[i]) / ray.d[i] and tFar = (max[i] - ray.o[i]) / ray.d[i]. We use the inverse of the ray direction to avoid repeated division. If the ray direction is negative along that axis, tNear and tFar are swapped so that tNear always represents the entry and tFar the exit.

We then progressively narrow the running intersection interval [t0, t1] by taking t0 = max(t0, tNear) and t1 = min(t1, tFar) for each axis. If at any point t0 > t1, the intervals no longer overlap and we immediately return false since the ray misses the box. If all three axes are processed without this condition triggering, the ray intersects the box within [t0, t1] and we return true with t0 and t1 updated to the entry and exit times.

Task 3

For BVH traversals, we implemented two functions intersect and has_intersection. While has_intersection checks whether any primitive in the BVH intersects the ray, intersect finds the closest intersection along the ray.

For both functions, we first test whether the ray intersects the node's bounding box using the slab method from Task 2, passing in the ray's current [min_t, max_t] interval. If the bounding box is missed, we immediately return false without touching any primitives inside.

If the node is a leaf, we iterate over all primitives in [node->start, node->end) and test each one individually. In has_intersection, we return true as soon as any primitive reports a hit. In intersect, we accumulate all hits and return whether any occurred, since each primitive's own intersect function updates both the Intersection struct and ray.max_t when it finds a closer hit, the closest intersection is tracked automatically without extra bookkeeping in the BVH.

If the node is an interior node, we recursively traverse both children. In has_intersection, we short-circuit and return true as soon as either child reports a hit. In intersect, we always traverse both children because a farther bounding box could still contain a closer primitive along the ray. The combined result is the OR of both children's return values, with ray.max_t continuously shrinking as closer hits are found, which also serves to prune traversal on subsequent box tests.

Part 3: Direct Illumination

Uniform Hemisphere Sampling Implementation

For uniform hemisphere sampling, I estimated direct lighting at each surface intersection by randomly sampling directions uniformly over the hemisphere above the hit point. I first constructed a local coordinate frame using make_coord_space whose z-axis aligns with the surface normal, so incoming sample directions could be generated in object space with the normal pointing upward. For each of the num_samples = scene->lights.size() * ns_area_light sampled directions, I used hemisphereSampler->get_sample() to get a random object-space direction, transformed it into world space using the o2w matrix, and cast a shadow ray from the hit point with min_t = EPS_F to avoid self-intersection. If that ray intersected an emissive surface, I retrieved the emission using get_emission() and treated it as incoming radiance. I then accumulated the Monte Carlo estimator using the diffuse BSDF value from isect.bsdf->f(w_out, wi_obj), the cosine term wi_obj.z (since the normal is aligned with z in object space), and the uniform hemisphere pdf of 1/(2π), then averaged over all samples. This method is unbiased but inefficient because it samples the entire hemisphere without regard to where the lights actually are, most sampled directions miss the light source entirely and contribute zero illumination, leading to high variance and noisy renders.

Light Importance Sampling Implementation

For light importance sampling, I estimated direct lighting by sampling the scene's light sources directly instead of sampling arbitrary hemisphere directions. At each hit point, I again constructed a local coordinate frame and computed the outgoing direction w_out in object space. I then looped over every light in the scene using scene->lights and sampled directions toward that light using light->sample_L, which returns the incoming radiance, sampled world-space direction, distance to the light, and the corresponding pdf. For delta lights such as point lights I used one sample since they have no area, while for area lights I used ns_area_light samples. After converting the sampled light direction into object space using the w2o matrix, I skipped samples where cos_theta <= 0 since the light is behind the surface. I then cast a shadow ray toward the light with min_t = EPS_F and max_t = dist_to_light - EPS_F so that only occluders between the surface and the light would count as blocking. If the shadow ray was unoccluded, meaning bvh->intersect returned false, I accumulated the reflected contribution using the BSDF, cosine term, and light-sampling pdf, then averaged across samples per light and summed contributions over all lights. Because this method concentrates samples directly on the actual light sources, it uses samples far more efficiently and converges much faster than uniform hemisphere sampling.

Comparison Between Uniform Hemisphere Sampling and Light Importance Sampling

On CBspheres_lambertian, the difference between uniform hemisphere sampling and light importance sampling was immediately obvious. With uniform hemisphere sampling, the image was noisy almost everywhere the spheres, walls, and floor were all covered in heavy speckles because most randomly sampled hemisphere directions never hit the ceiling area light and contributed zero radiance. The shadow regions underneath the spheres were particularly poorly defined, appearing as random dark patches rather than coherent soft shadows. With light importance sampling, the image converged much faster because every sample was aimed directly at the actual light source. The walls and upper portions of the scene became smooth almost immediately, and the soft shadows beneath the spheres were far more well-defined even at the same sample count. The remaining noise in the importance sampled render was concentrated in the shadow penumbra regions, which is expected since those regions require more samples to accurately estimate the partial occlusion. Overall, light importance sampling produced a dramatically cleaner result for the same computational budget, demonstrating that concentrating samples where they contribute most directly on the lights is far more efficient than uniform hemisphere sampling.

Part 4: Global Illumination

Implementation of the Indirect Lighting Function

To implement indirect lighting, I extended the at_least_one_bounce_radiance function to recursively trace rays beyond the first bounce. At each intersection point, I first constructed a local coordinate frame with the surface normal aligned to the z-axis, computed the hit point and outgoing direction in object space. I then always added the direct one-bounce contribution using one_bounce_radiance as the base of the accumulated radiance. To simulate additional bounces, I sampled a new incoming direction using the BSDF's sample_f function, which returns a cosine-weighted direction in object space along with the corresponding pdf. I converted this direction to world space, constructed a new ray from the hit point with min_t = EPS_F and depth decremented by one, and recursively called at_least_one_bounce_radiance on the new intersection if one existed. The indirect contribution was accumulated using the full reflection equation multiplying the BSDF value, the recursive radiance, and the cosine term, then dividing by the pdf. To support the isAccumBounces flag for isolating individual bounces, I only added the direct one-bounce contribution when isAccumBounces was true or when the ray was at the final bounce depth. For Russian Roulette termination, I used a continuation probability of 0.65 and always traced at least one indirect bounce when the ray depth equaled max_ray_depth, applying the roulette only for subsequent bounces and normalizing by the continuation probability accordingly.

Part 5: Adaptive Sampling

Adaptive sampling is a technique that avoids using a fixed high number of samples for every pixel by concentrating samples in the parts of the image that are harder to render regions with high variance such as shadow boundaries, complex geometry, and areas with indirect lighting while terminating early for pixels that converge quickly such as flat uniformly lit surfaces. This is more efficient than uniform sampling because easy pixels waste samples if forced to use the same count as difficult pixels. The core idea is to track running statistics about the illuminance of samples taken so far and use a statistical convergence test to decide when a pixel has received enough samples. Specifically, we compute a 95 percent confidence interval half-width I = 1.96 * sigma / sqrt(n), where sigma is the standard deviation of the illuminance samples and n is the number of samples taken so far. If I is less than or equal to maxTolerance * mu, where mu is the mean illuminance and maxTolerance is 0.05 by default, we conclude the pixel has converged and stop sampling it. This gives an unbiased and statistically principled stopping criterion that naturally allocates more samples to difficult regions and fewer to easy ones.

Adaptive Sampling Implementation

I implemented adaptive sampling inside the raytrace_pixel function. Rather than always taking exactly ns_aa samples per pixel, I maintained three running variables: s1 as the sum of illuminance values, s2 as the sum of squared illuminance values, and n as the actual number of samples taken so far. For each new sample, I generated a camera ray with a jittered pixel coordinate, traced it through the scene using est_radiance_global_illumination, and added the resulting radiance to the running sum. I then computed the illuminance of the sample using L.illum() and updated s1 and s2 accordingly. To avoid checking convergence after every single sample, which would be expensive, I checked the convergence criterion only every samplesPerBatch samples. At each check, I computed the mean as mu = s1 / n and the variance as sigma_sq = (1 / (n - 1)) * (s2 - s1 * s1 / n), then computed I = 1.96 * sqrt(sigma_sq) / sqrt(n). If I was less than or equal to maxTolerance * mu, I broke out of the sampling loop early. After the loop, I normalized the accumulated radiance by the actual number of samples taken n rather than ns_aa, updated the sample buffer with the averaged color, and stored the actual sample count in sampleCountBuffer so that the sampling rate visualization image could be generated correctly showing which pixels required more or fewer samples.

(Optional) Part 6: Extra Credit: Jittered Sampler

For extra credit, we implemented a jittered (stratified) pixel sampler as an alternative to the default uniform random sampler. Instead of placing all samples randomly within the pixel, we divide the pixel into an n×n grid of strata and place exactly one sample within each stratum, randomly positioned inside it. This guarantees better coverage of the pixel area, reducing the clumping and gaps that pure random sampling tends to produce.

At low sample counts, jittered sampling produces noticeably less noise and aliasing compared to uniform random sampling. At s=4, jittered sampling has less clumping noise because each pixel's 4 samples are placed in a 2×2 grid, preventing them from clustering together. Uniform's 4 random samples might all land near one corner of the pixel, leaving large areas unsampled. At s=16, jittered uses a 4×4 grid, giving better coverage of the unit square and producing smoother gradients on surfaces. At s=64, both methods converge toward the ground truth, but jittered typically converges faster, and the noise at 64 samples per pixel with jittered looks closer to what uniform achieves at 128 samples per pixel.
